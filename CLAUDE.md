# Working agreement

- **Discuss before coding.** When Dan asks "can we do X?" or floats an idea,
  respond with an assessment and a proposed approach first — do NOT edit code,
  push commits, or open PRs until the approach has been talked through and
  Dan says to go ahead. Only make changes immediately when the request is an
  explicit instruction to implement something already agreed on.
- Never push to `main` directly; work on a feature branch and wait for Dan
  to approve a merge.
